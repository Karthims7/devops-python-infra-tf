# Advanced Terraform Interview Q&A for Senior DevOps

### Q1: How do you handle refactoring without destroying and recreating resources?
- Use the `moved` block introduced in Terraform 1.1+:
  ```hcl
  moved {
    from = aws_instance.web
    to   = module.web_server.aws_instance.this
  }
  ```
  - Unlike CLI commands (`terraform state mv`), `moved` blocks can be version-controlled, reviewed in PRs, and safely executed by CI/CD without manual state surgery.
- For bringing unmanaged infrastructure into Terraform, use the `import` block:
  ```hcl
  import {
    to = aws_s3_bucket.logs
    id = "my-existing-bucket-name"
  }
  ```

### Q2: What causes state locking issues and how do you recover safely?
- **Cause:** When a team member or CI pipeline runs `terraform plan` or `terraform apply`, Terraform acquires a lock ID in DynamoDB / backend. If the runner is killed abruptly (OOM, container restart, network disconnect), the lock may remain orphaned.
- **Resolution:**
  1. Verify no pipeline or engineer is actively running an apply.
  2. Use `terraform force-unlock <LOCK-ID>` with extreme care.

### Q3: How do you prevent sensitive values from leaking into Terraform state files and CI logs?
- **Marking variables sensitive:** Use `sensitive = true` on variables and outputs to suppress printing in CLI/CI logs.
- **State file security:** State files inherently contain plain-text resource attributes (including DB passwords and tokens if generated by Terraform). Mitigations:
  - Never store state in Git.
  - Store in encrypted S3/GCS with strict KMS encryption and least-privilege IAM policies.
  - Avoid generating passwords directly in Terraform; instead, integrate with AWS Secrets Manager or HashiCorp Vault.

### Q4: How do you manage large Terraform codebases at scale without performance degradation?
- Large monolithic state files cause `terraform plan` to become painfully slow (taking 15–30+ minutes because Terraform refreshes every cloud resource API).
- **Solutions:**
  1. Decouple by domain into smaller state boundaries (Network, Compute, Data, Apps).
  2. Use `-target` only during emergency hotfixes (never in standard CI).
  3. Use `-refresh=false` during plan if refresh overhead is prohibitive, or use scheduled drift detection.
  4. Use Terragrunt or Terraform Cloud Workspaces to orchestrate independent micro-states.
